## 1. 판정 요약

이번 문서는 코드 수정 결과가 아니라 각 발견사항의 독립 해결 설계다. 실행형 PoC, 운영 Cloudflare/TLS, dependency advisory, 실제 secret 강도는 확인하지 않았다. 따라서 “해결 완료”가 아니라 구현·검증 backlog로 취급한다.

| 우선순위 | 항목 | 심각도 |
|---|---|---|
| P0 | 공개 게임 생성 자원 고갈 | High |
| P1 | 전화번호만으로 coupon bearer 회수, 사업자 통제권 미검증, 공개 signup 자원 고갈, 프록시 rate-limit 식별자, AI history PII 우회, 운영 Nginx 선택 오류 | Medium |
| P2 | 로그인 limiter cardinality, CSV 수식 주입, 약한 phone HMAC 키 | Low |

## 3. 권장 실행 순서

1. 공통 trusted-proxy와 지속형 rate-limit/ quota 기반을 먼저 구현한다.
2. 공개 게임 생성과 signup에 저장공간·행 수·429 보호를 적용한다.
3. 고객 상태 응답에서 bearer token을 직접 노출하지 않는 회수 흐름을 설계한다.
4. 셀프가입의 통제 증명·복구와 운영 Nginx production profile을 병행한다.
5. AI 입력 경계를 중앙화하고 CSV·HMAC·로그인 limiter 같은 저위험 항목을 마무리한다.

## 4. 잠긴 규칙 보존

- QR을 가진 고객의 게임 진입은 staff approval이나 SMS를 필수화하지 않는다.
- 결과는 SecureRandom으로 서버가 선택·저장하고 게임/쿠폰은 원자적으로 커밋한다.
- `store_id` 격리, 2일 Asia/Seoul cooldown, coupon snapshot·중복 redemption 방지를 유지한다.
- AI에는 고객 개인정보·token·PIN·JWT·API key를 보내지 않고 aggregate/read-only/store-bound 도구만 허용한다.
- YUT_REVIEW/REVIEW_PILOT/SODAM 광고 consent 분리와 철회 규칙을 변경하지 않는다.

## 5. 완료 판정 및 검증 계획

구현 후 `./gradlew test`, 실제 frontend scripts(`lint`, `test`, `build`가 존재하는 경우), Docker Compose `up -d --build`, Nginx 경유 health/API, trusted-proxy 시뮬레이션, 반복 redemption/idempotency, signup/game 부하 테스트를 수행한다. Cloudflare Quick Tunnel과 production TLS는 실제 환경에서 별도 확인해야 하며, 확인 전에는 완료로 표시하지 않는다.

## 6. 현재 미검증 경계

정적 검토에서 제외된 generated/binary 및 `.claude/skills/**`, 실제 배포 topology, host secret store·rotation, PostgreSQL 운영 ACL/backup, 외부 provider 동작, dependency CVE, 다중 backend replica는 별도 검증이 필요하다.
